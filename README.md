# task-tracker

Трекер задач для локальных проектов. Задачи хранятся md-файлами, проект и метки задаются полями
задачи. Служба отдаёт задачи через REST, сырым markdown по ссылке, как MCP-сервер для
AI-агентов (Claude Code и другие MCP-клиенты) и как канбан-доску в браузере.

Цель — общий список задач для своих проектов и агентов, которые над ними работают: агент
ставит задачу в соседний проект, берёт постановку, пишет комментарии и двигает статус. Человек
видит то же самое на доске или прямо в файлах.

## Безопасность

> **Внимание.** task-tracker рассчитан на локальную машину или доверенную частную сеть.
> Средств безопасности в нём нет.

- **Аутентификации и авторизации нет.** Кто достучится до порта, тот читает, создаёт и правит
  любые задачи через REST, доску и MCP.
- **Шифрования нет.** Служба говорит по обычному HTTP. Для HTTPS нужен свой обратный прокси.
- **MCP не проверяет заголовок `Host`.** Так клиенты могут подключаться по адресу машины в
  частной сети, но защиты от DNS rebinding из-за этого нет.
- Заголовок `X-Project` — это просто метка подключения, а не учётная запись: его может
  подставить кто угодно.
- Ограничений частоты запросов и квот нет.

При запуске из пакета служба по умолчанию слушает только `127.0.0.1`. Открывать её в сеть
(`TT_HOST=0.0.0.0`, `docker -p 8113:8113`) стоит только в сети, где доверяете всем участникам.
**Не выставляйте службу в интернет** без обратного прокси с аутентификацией и TLS.

Защищено только содержимое задач, которое показывает доска: сырой HTML из markdown экранируется,
ссылки `javascript:` не создаются.

## Требования

- Python 3.12 или новее;
- `git` в `PATH`, если нужна история изменений задач (`TT_GIT=1`, включено по умолчанию);
- либо Docker вместо Python.

## Установка и запуск

### Из исходников

Linux / macOS:

```bash
git clone https://github.com/alex-venediktov/task-tracker.git
cd task-tracker
python3 -m venv .venv
.venv/bin/pip install -e .
TT_DATA_DIR=~/tasks .venv/bin/tracker
```

Windows (PowerShell):

```powershell
git clone https://github.com/alex-venediktov/task-tracker.git
cd task-tracker
python -m venv .venv
.venv\Scripts\pip install -e .
$env:TT_DATA_DIR = "$HOME\tasks"; .venv\Scripts\tracker
```

Откройте `http://localhost:8113/`: там доска. Каталог задач создаётся при старте, если его нет.

### Docker

```bash
docker build -t task-tracker .
docker run -d --name task-tracker --restart unless-stopped \
  -p 127.0.0.1:8113:8113 \
  -v "$HOME/tasks:/data" \
  -e TZ=Europe/Moscow \
  task-tracker
```

- В контейнере служба слушает `0.0.0.0`. Что видно снаружи, решает публикация порта:
  `-p 127.0.0.1:8113:8113` открывает её только этой машине, `-p 8113:8113` — всей сети.
- Время задач пишется по часам контейнера. Задайте `TZ`, иначе будет UTC.
- Чтобы задачи можно было править руками на хосте, запускайте контейнер под своим uid:
  `--user "$(id -u):$(id -g)" -e HOME=/tmp`.

### Настройки

Настройки задаются переменными окружения, образец лежит в `.env.example`.

| Переменная | По умолчанию | Что |
|---|---|---|
| `TT_DATA_DIR` | `data` (в образе `/data`) | каталог с md-файлами задач |
| `TT_HOST` | `127.0.0.1` (в образе `0.0.0.0`) | адрес, который слушает служба |
| `TT_PORT` | `8113` | порт |
| `TT_PUBLIC_URL` | пусто | внешний адрес для ссылок на задачу в ответах, например `http://localhost:8113`; пусто — ссылки относительные |
| `TT_GIT` | `1` | `1` — каждая запись коммитится в git каталога данных, `0` — без истории |

### Разработка

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]"      # Windows: .venv\Scripts\pip
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check .
```

## Хранилище

```
<TT_DATA_DIR>/
  1.md     project: my-app
  2.md     project: homelab
  3.md     project: my-app
```

- id задачи по умолчанию — сквозной номер, следующий за наибольшим номером в каталоге. id можно
  задать при создании или сменить позже: латинские буквы, цифры, `-`, `_`, до 64 знаков,
  уникален без учёта регистра. При смене id файл `<id>.md` переименовывается, и прежняя ссылка
  `/t/<id>.md` перестаёт работать;
- файл, имя которого не номер, считается задачей, только если в его frontmatter указан тот же `id`;
- проект — это поле `project`: строчные латинские буквы, цифры и дефис. Список проектов
  собирается из значений этого поля. Смена поля переносит задачу в другой проект, номер и ссылка
  при этом не меняются;
- файл без поля `project` (например, положенный руками) виден только в списке всех задач;
- файл читается с диска на каждый запрос, поэтому правка руками видна сразу;
- при `TT_GIT=1` каждая запись — это коммит в git каталога данных. Сбой git запись не отменяет;
- удаления в службе нет: ненужную задачу переводят в `done` с комментарием, файл удаляют руками.

Файл задачи:

```markdown
---
id: 3
project: my-app
title: Поиск по тегам
status: todo
author: human
created: 2026-10-11T20:40
updated: 2026-10-11T20:40
tags: [search]
---

## Цель
...

## Что сделать
...

## Готово, когда
...

## Обсуждение

### 2026-10-11 21:00 - my-app

взял в работу
```

Статусы: `backlog`, `todo`, `doing`, `review`, `done`. Ключи frontmatter, которых служба не знает,
при правке сохраняются.

## Доска

`http://<хост>:8113/` — канбан-доска, `/?p=<проект>&t=<метка>` открывает её с фильтрами.
Страница статическая (`tracker/web/`), без JS-библиотек и CDN, данные берёт только из REST ниже.
markdown в HTML переводит служба (`markdown-it-py`).

- в шапке фильтры: проект (или все проекты — тогда проект виден на карточке) и метка. Щелчок по
  метке на карточке включает фильтр по ней;
- колонки соответствуют статусам из `/api/statuses`, «+» в колонке создаёт задачу с этим статусом;
- перетаскивание карточки в другую колонку меняет `status` в файле. На сенсорном экране статус
  меняется в окне карточки;
- в окне карточки: заголовок, проект (его смена переносит задачу), статус, метки, текст на
  вкладках «Просмотр» (HTML) и «Правка» (markdown), комментарий. Кнопка «Ссылка» копирует адрес
  `/?task=<id>`, который открывает доску сразу с окном этой задачи;
- пока вкладка видна, доска перечитывает задачи раз в 15 секунд, так что ручные правки файлов и
  задачи от агентов появляются сами. Карточки в колонке упорядочены по номеру задачи.

## REST

| Метод | Путь | Что |
|---|---|---|
| GET | `/healthz` | живость |
| GET | `/api/statuses` | статусы и подписи колонок |
| GET | `/api/projects` | проекты с числом задач по статусам |
| GET | `/api/tags?project=` | метки с числом задач |
| GET | `/api/tasks?project=&status=&tag=` | краткий список задач, фильтры необязательны |
| POST | `/api/tasks` | создать: `project`, `title`, `body`, `status`, `tags`, `author`, `id` (необязательно) |
| GET | `/api/tasks/{id}` | задача целиком |
| PATCH | `/api/tasks/{id}` | правка `title`, `body`, `tags`, `project`, `id` |
| POST | `/api/tasks/{id}/move` | смена статуса: `status` |
| POST | `/api/tasks/{id}/comments` | комментарий: `text` |
| GET | `/t/{id}.md` | исходный md-файл задачи, `text/markdown` |
| POST | `/api/markdown` | предпросмотр: `text` -> `{"html": ...}` |

## MCP

Транспорт Streamable HTTP на `/mcp`, без сессий, ответы в JSON. Подключение называет свой проект
заголовком `X-Project`: туда попадают задачи без явного `project`, и это же имя записывается
автором.

```
claude mcp add --transport http task-tracker http://localhost:8113/mcp --header "X-Project: my-app"
```

То же самое записью в `.mcp.json` проекта:

```json
{
  "mcpServers": {
    "task-tracker": {
      "type": "http",
      "url": "http://localhost:8113/mcp",
      "headers": { "X-Project": "my-app" }
    }
  }
}
```

Инструменты: `list_projects`, `list_tasks`, `get_task`, `create_task`, `update_task`, `move_task`,
`comment_task`. Задачу можно поставить в соседний проект — `create_task(project="homelab", ...)` —
и перенести между проектами — `update_task(task_id, project=...)`. `list_tasks` фильтрует по
проекту, статусу и метке (`tag`).

## Задача как постановка для агента

Полный текст задачи отдают `get_task(task_id, markdown=true)` и `GET /t/{id}.md`. Этот текст можно
передать агенту как постановку без изменений, например в `/volna:task` плагина «Волна».
